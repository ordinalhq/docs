---
title: "post.approval.requested"
description: "Fired when someone requests approval from users for a post"
sidebar:
  label: "post.approval.requested"
---

All webhook payloads follow a consistent top-level structure with event-specific data nested within the `data` object.

<TypeTable
  type={{
    "type": { type: "string", required: true, description: "The event type (e.g. post.approval.requested)." },
    "data": { type: "object", required: true, description: "Event-specific payload for this webhook." },
    "data.approval": { type: "object", required: true, description: "Approval request context for the post." },
    "data.approval.post": { type: "object", required: true, description: "Post being approved. Contains id, title, and url." },
    "data.approval.campaign": { type: "object", description: "Campaign the post belongs to, if any. Contains id, name, startDate, and endDate." },
    "data.approval.workspace": { type: "object", required: true, description: "Workspace the post belongs to. Contains id, slug, and name." },
    "data.approval.createdApprovals": { type: "array", required: true, description: "New approval requests created by this action. Each item has id, isBlocking, message, dueDate, createdAt, status (Requested), user (approver), and requestedBy (who asked for approval). User objects contain id, firstName, lastName, and email. Dates are ISO 8601 strings where present." },
    "data.approval.existingApprovals": { type: "array", required: true, description: "Approvals already on the post before this request. Each item is either a requested approval (status Requested) or an approved one (status Approved). Approved items include approvedAt and approvedBy." },
    "createdAt": { type: "string", required: true, description: "ISO 8601 timestamp when the webhook event was created." },
  }}
/>
